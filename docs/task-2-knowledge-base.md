# Задание 2. Подготовка базы знаний

## Исходная предметная область

В качестве исходной предметной области была выбрана вселенная Star Wars на базе материалов Wookieepedia / Star Wars Fandom.

Эта предметная область известна большинству LLM, поэтому исходные тексты нельзя использовать напрямую: модель может ответить по памяти, без обращения к RAG-индексу.

## Подход

Для подготовки базы знаний был использован следующий подход:

1. Выбран список из 30+ страниц по ключевым сущностям:
   - персонажи;
   - организации;
   - технологии;
   - планеты;
   - события;
   - объекты.

2. С помощью Python-скрипта `scripts/build_knowledge_base.py` тексты были загружены через API.

3. Тексты были очищены от лишнего форматирования.

4. Через словарь `terms_map.json` были заменены ключевые имена, названия организаций, планет, технологий и событий.

5. Финальные документы сохранены в папку `knowledge_base/`.

## Зачем нужна замена терминов

Замена терминов нужна, чтобы LLM не могла ответить на вопросы по памяти. После подмены сущностей база знаний становится отдельным вымышленным миром, который модель не знает заранее.

Например:

- `Darth Vader` → `Varn Kaldor`
- `Death Star` → `Void Core`
- `The Force` → `The Lumen Field`
- `Jedi Order` → `Aurelian Circle`
- `Galactic Empire` → `Aurelian Dominion`

## Результат

В результате получена локальная база знаний:

- `knowledge_base/` — 30+ документов в формате Markdown;
- `terms_map.json` — словарь замен;
- `scripts/build_knowledge_base.py` — скрипт генерации базы;
- `scripts/validate_knowledge_base.py` — скрипт проверки, что оригинальные термины не остались в финальных документах.

Финальная база знаний не должна распознаваться моделью как Star Wars и будет использоваться для построения RAG-индекса.
